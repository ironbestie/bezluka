## 📖 О проекте

**БезЛука** решает ключевые проблемы индустрии HoReCa: отсутствие прозрачности загруженности залов, разрозненные программы лояльности, слабая мотивация персонала и сложность синхронизации броней из разных источников.

Проект представляет собой современное веб-приложение, где:
- 👤 **Гости** видят реальную загруженность, уровень шума и скорость обслуживания *до* визита, копят баллы и выполняют миссии.
- 👔 **Владельцы** получают B2B-дашборд с аналитикой LTV, повторных визитов, источников бронирований и прозрачных рейтингов персонала (CSAT, чаевые, жалобы).
- 🔄 **Система** бесшовно синхронизирует брони с внешними агрегаторами и кассовыми системами (iiko, R-keeper).

## 🔌 Архитектура интеграций

Система спроектирована как **Hub (центральный хаб)** для агрегации потоков данных:
1. **Входящие вебхуки:** Принимаем брони от OpenTable, TheFork, LeClick и др. через защищенные эндпоинты (`/api/webhooks/`).
2. **Маппинг:** Каждый ресторан имеет поле `external_ids` (например, `{"iiko": "uuid-123", "thefork": "id-456"}`), что позволяет мгновенно сопоставлять внешние события с внутренними записями.
3. **Асинхронная обработка:** При создании брони задача ставится в очередь **Celery**. Система пытается отправить данные в POS (iiko/R-keeper). При сбое API происходят автоматические повторные попытки (retry), а при критической ошибке менеджер получает уведомление.
4. **Идемпотентность:** Все внешние запросы проверяются по `external_booking_id` для предотвращения дублирования.
